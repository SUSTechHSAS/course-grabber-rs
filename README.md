# 教务系统抢课 · Rust 版

[course-grabber](https://github.com/SUSTechHSAS/course-grabber) 的 Rust 重写：
**放课瞬间精准首发 + 持续捡漏**，带自动登录、被踢重登录、写请求限流节拍器，
以及对服务器过载的容错。点选验证码的识别**直接编进可执行文件** ——
一个 **841,008 字节（821 KiB）** 的文件就是全部，不需要 Python、不需要动态库、不需要模型文件。

> 这是一个**配置驱动**的工具：域名、接口路径、Cookie 名、密码加密密钥、候选教学班
> 全部写在本地 `config.json` 里（已被 `.gitignore` 忽略），仓库代码里没有任何具体学校的信息。
> 配置格式与原版**完全一致** —— 原来那份 `config.json` 可以原样拷过来。

```
                    ┌──────────────┐
   学号 + 密码 ───► │  自动登录     │ ──► 会话(token + cookie)
                    │  auth.rs     │        │
                    └──────────────┘        │ 被限流踢掉时自动重登
                            ▲               ▼
   19:50 启动 ──► 只读预检 ──► 对齐服务器时钟 ──► T0 错开首发 3 个班
                                                    │
                                            重试循环（捡漏，只读探空位）
                                                    │
                                       已选课程列表出现目标教学班 = 成功
```

## 1. 体积与速度

| | 原版（Python + PyInstaller） | 本仓库 |
| --- | ---: | ---: |
| 可执行文件 | 8,727,128 字节（8.3 MiB） | **841,008 字节（821 KiB）** —— 10.4× |
| 下载的压缩包 | 8,623,811 字节（8.2 MiB） | **493,183 字节（482 KiB）** —— 17.5× |
| 运行时依赖 | 无（但打包时收了 CPython 解释器与标准库） | 无（一个静态链接好的二进制） |
| 验证码识别 | `libccm.so` + `python/solver.py`（约 250 KB，还要配对路径） | 编译进来的 Rust 依赖，模型 124 KB 编在二进制里 |
| 启动 | 解包 + 解释器启动约 0.3~1 s | 进程直接跑，毫秒级 |

识别本身用的就是 [click-captcha-matcher-rs](https://github.com/SUSTechHSAS/click-captcha-matcher-rs)
里的同一份代码与同一个模型（w16），所以**速度与准确率与那个库的实测数据一致**
（Ryzen 7 5700U 上 1.64 ms/张），没有为了压体积牺牲推理性能 ——
`opt-level` 全局用 `"s"`，那个 crate 单独抬回 `3`。

"无缝衔接"具体指：识别是一个**编译期依赖**，于是下面这些坑全都不存在了 ——
找不到 `libccm.so`、`python/` 目录指错、模型文件路径不对、`sys.path` 里同名模块串味、
打包时忘了带模型、换解释器重跑。一个文件拷过去就能跑。

## 2. 快速开始

### 下载预编译版

到 [Releases](https://github.com/SUSTechHSAS/course-grabber-rs/releases) 下载对应平台的一键包，
解压后直接跑：

```bash
./run.sh          # Linux / macOS
run.bat           # Windows（双击）
```

第一次运行会在可执行文件旁边生成 `config.json` 并告诉你该填什么。
**不需要装任何东西** —— 不需要 Python，不需要 Rust，不需要动态库。

### 从源码构建

```bash
git clone https://github.com/SUSTechHSAS/click-captcha-matcher-rs ../click-captcha-matcher-rs
git clone https://github.com/SUSTechHSAS/course-grabber-rs
cd course-grabber-rs
cargo build --release          # 产物：target/release/course-grabber
```

识别库必须 clone 到**同级目录**（它是 path 依赖）。构建只需要 cargo，
`cargo build --release` 出来的那一个文件就是全部。

### 三步走

```bash
# 1) 配置（把原版的 config.json 拷过来也行）
cp config.example.json config.json
$EDITOR config.json          # 填域名、接口路径、Cookie 名、候选教学班……

# 2) 凭据（要用自动登录的话）
mkdir -p ~/.config/course-grabber
cat > ~/.config/course-grabber/credentials.json <<'EOF'
{"student_id": "你的学号", "password": "你的密码"}
EOF
chmod 600 ~/.config/course-grabber/credentials.json

# 3) 演练（只读预检，绝不提交）→ 实战（19:50 启动，自己等到 20:00:00.000 首发）
./target/release/course-grabber
./target/release/course-grabber --live
```

见到「预检全部通过」再等放课。**不加 `--live` 永远不会提交任何东西。**

## 3. 常用开关

`--help` 里有全部参数，这里只列最常用的：

| 参数 | 说明 |
| --- | --- |
| `--live` | 真正提交。不加就只做只读预检 |
| `--at 20:00:00` | 出手时刻（配置时区）。已过则立刻开打，`--tomorrow` 才等到明天 |
| `--now` | 不等了，立刻开打 |
| `--window 90` | 出手后持续尝试多少秒 |
| `--priority 001,002` | 覆盖配置里的候选顺序（可只写 ID 后缀） |
| `--single` | 首发只打第一优先级那一个班（默认打组内前 3 个） |
| `--stagger 0.10` | 多班首发之间错开多少秒 |
| `--write-timeout 4` | 单发写请求最长占用几秒（爆发期自动压到 2 秒） |
| `--no-relogin` | 关掉自动登录链路，只用 `--cookie` / `--url` 给的会话 |
| `--relogin-max 4` | 一次运行最多自动登录几次 |
| `--offline` | 不联网，只打印将要发送的报文 |

**随时可以停**：`Ctrl-C` 是优雅停止（不再发新请求 → 收尾 → 打印结果），再按一次立刻退出。

## 4. 安全设计（写在代码里的硬约束）

1. **没有任何退选/删除志愿的代码路径**，全文不含 `operationType":"2"`。
   没有任何函数能移除你已选的课程。（CI 里有一条测试专门断言提交报文里的
   `operationType` 恒为 `"1"`。）
2. **默认不提交**，必须显式 `--live`。
3. **已在已选列表 → 直接退出**，不做任何提交。
4. **白名单**：只提交预检阶段解析出的候选教学班。
5. **只认已选列表**：提交接口说「成功」不算成功，必须已选课程里出现完整教学班 ID。
6. **密码错立刻熔断**：服务端回「登录名或密码不正确」就永久放弃自动登录，
   绝不用错误密码反复试探（避免账号被锁）。
7. **写请求绝不自动重放**：只读请求被判过期会自动重登并重放，写请求不会 ——
   避免重复提交。
8. **写请求节拍器**：所有写请求（首发 + 重试）共用同一份额度，任何路径都凑不出
   超出「每滚动窗口 N 发」的第 N+1 发。

## 5. 工程笔记（这些结论都是实测出来的，代码把它们固化成了硬约束）

### 写接口的限流模型

在一套实际系统上量到的（换成你自己的学校务必重测）：

- **滚动 1 秒内最多 3 发写请求**，第 4 发会返回「请求过快」并且**当场作废整个会话**。
- 1 发/秒、2 发/秒可以一直打，没有累计上限。
- **只读请求不占写额度**。
- **多发「同时」发 ≠ 多次机会**：同一瞬间打出去的 3 发里只有 1 发会被真正评估，
  另外 2 发拿到的是空 msg 的并发拒绝；**错开 0.06 秒以上**才是 3 次真机会。
- 被限流作废的会话不会自己恢复，但**重登录能立刻刷新额度**。

`pacer.rs` 就是把这些变成代码里的硬约束：窗口内最多 N 发、相邻两发至少错开
`min_gap`、并且「遗忘」一条记录要等满 `窗口 + 安全边界`（贴着边界发会踩线）。

顺带说明：原版 Python 里 `pacing.min_gap` / `http.write_timeout` 这两个配置键其实
**不生效**（代码写死了命令行默认值）。Rust 版让它们生效了，所以换学校时改配置就有用。

### 服务器过载时会发生什么

放课瞬间全校同时提交，服务端会过载：请求挂住不回、网关 5xx、返回 HTML 错误页。
原版在这里会「死等」（一次写请求 15 秒超时 × 内部重试 2 次 = 30 秒），
一个挂住的请求就能吃掉整个窗口。用「会按剧本过载的假学校」量过的对比：

| 过载剧本（20 秒窗口，前 3 秒过载） | 改之前 | 改之后 |
| --- | ---: | ---: |
| 连接挂住不回 | 2 发 / **16.1 秒** | 6 发 / **3.9 秒** |
| 响应慢 6 秒 | 2 发 / **16.1 秒** | 6 发 / **3.9 秒** |
| 网关 502 + HTML | 7 发 / 3.1 秒 | 9 发 / 3.6 秒 |

### 目标时刻已过就直接开打（预检按需裁剪）

`--at` 的时间已经过了（或 `--now`）时，脚本会自动跳过**只为"精确对点"服务的预检**：

| 步骤 | 对点时 | 已过点时 |
| --- | --- | --- |
| 校验会话 | 做 | **做**（必须） |
| 读已选课程（安全护栏） | 做 | **做**（40ms） |
| 从课程目录解析候选 | 做 | 跳过（候选直接用配置里的） |
| 容量快照 | 做 | 跳过 |
| 对齐服务器时钟（25 次采样） | 做 | **跳过（省约 2.5 秒）** |

实测：会话建立之后到写出第一发，**从 2.7 秒降到 39 毫秒**；整进程从启动到出手约 1.5~2 秒。

### 服务端「正在初始化」时**绝不能安静下来**（一次真实事故）

放课瞬间服务端会进入一段「系统正在初始化」的状态，实测持续了**约 3 分钟**。这段时间：

- 写请求全部被拒：「正在初始化，请稍候…」
- **容量接口返回 `0/0`** —— 那是"没有数据"，不是"没有空位"
- 已选课程列表返回空、课程目录返回空
- 会话可能被清掉，登录接口短暂返回 `认证失败`

**踩过的坑**：脚本里有个"先读容量、没空位就不发写请求"的优化。初始化期间容量返回
`0/0`，被算成"已满"，于是脚本在**整个放课窗口里安静地轮询了 56 秒**，一发写请求都没发出去。

两处修正：`has_slot()` 把 `total <= 0` 当成"查不到"（返回「照打」）；
初始化期间停机时间不计入"第一组多少秒没名额就换组"的倒计时，
并把试探节奏改成「每 0.6 秒 1 发」（多打无意义，但必须快速试探 ——
服务恢复的那一瞬间才是位子真正可抢的时刻）。

回归测试：`tests/offline.rs::init_outage_keeps_firing` 用一个"容量全返回 0/0 +
写请求全被拒"的假服务端驱动**真实的重试循环**，断言停机期间仍在发写请求。

> **放课当晚不要反复重启脚本。** 每次重启都要重新登录（同一账号单会话，还会顶掉
> 上一次的会话）+ 重新跑预检，首发那 3 发又会全部撞在"正在初始化"上。正确做法是
> 一个实例 + 足够长的 `--window`（比如 600 秒），它会自己等系统恢复。

### 同一账号只有一个会话

连续登录 A→B→C，每次都回头复查前面的会话：

```
登录 A 之后: A=活
登录 B 之后: A=死  B=活
登录 C 之后: A=死  B=死  C=活
```

推论：**跑脚本时别在浏览器里刷新同一套系统**，**只能跑一个实例**
（脚本用 PID 锁拦住了第二个），也**别指望多开会话把额度翻倍**。

## 7. 与原版（Python）的差异

**保留了**：配置格式、命令行参数的语义与默认值、全部安全约束、
上面那些实测出来的限流/对时/重试策略、退出码（0 抢到 / 1 没抢到 / 2 参数或配置问题 /
3 会话不可用 / 4 疑似双选需要人工处理）、日志的措辞与节奏。

**去掉了**：

- **读 Chrome Cookie 那条回退路径**。它的价值是"没有凭据文件时也能跑"，代价是
  要自己实现 SQLite 读取 + AES-128-CBC + PBKDF2 + Secret Service(D-Bus) ——
  而原版打包版里那条路其实也是**不通**的（`import dbus` 在打包环境里根本不存在，
  实际只会拿 "peanuts" 那把钥匙，桌面版 Chrome 早就不用它了）。
  现在会话来源是两个明确的东西：**凭据文件自动登录**，或者显式的 `--cookie` / `--url`。
  因此也去掉了 `--profile` / `--no-chrome`（保留为无操作参数，老命令不会报错）。
- **`tools/` 下那 7 个探针脚本**（rate-limit / burst-shape / concurrent /
  session-budget / sessions / overload / auth）。它们是"换学校时重新测限流参数"
  用的研究工具，依赖原版的 Python 模块；要重测请用原版仓库里那份，
  本仓库不再重复实现。
- `--captcha-model-dir`（识别库不再需要指向目录；`--captcha-model` 仍可用外部 `.ccm`）。
- Windows 上强制 UTF-8 输出的那段黑客代码（Rust 不会因为打印中文而崩）。
- Windows 上的"优雅停止"信号处理（CRT 的信号语义不同，见 `grab.rs` 的注释）。

**改掉的（都是原版里的坑）**：

| | 原版 | 这里 |
| --- | --- | --- |
| `pacing.min_gap` / `http.write_timeout` 配置 | 写了但不生效 | **生效**（命令行优先） |
| `--at` 写错了（如 25:00:00） | 跑完一半预检才崩，甩一个 `ValueError` traceback（退出码 1） | 联网之前就报一句人话（退出码同为 1） |
| 配置写错（缺 `paths.*`、4 组 `des_keys`、空串密钥） | 运行到一半才炸（`KeyError`/`TypeError`/`NameError`） | 启动时一句话说清楚哪一项不对 |
| 取验证码时网络抖动 | 整次自动重登录失败，白耗一次配额 | 在换码循环里重试（不消耗重登录配额） |
| 非 80 端口的 Referer | 漏端口 | 带上端口 |
| `config.example.json` 里"留空 des_keys = 明文提交" | 从未实现，留空会报错 | 仍然报错（但模板里写清楚了） |
| 打包 | PyInstaller，8.6 MB，要配 `libccm.so` 与模型路径 | `cargo build --release`，824 KB，一个文件 |
| 识别库加载失败时的表现 | 运行期才发现（找不到 .so / 目录指错） | 编译期就得存在；模型加载失败在预检前报错 |
| 无凭据时的学号来源 | 顺带读 Chrome 的 Session Storage | `--student` 或凭据文件（更明确，也更少读你的浏览器数据） |
| 横幅里的时区字样 | 硬写「北京时间」（时区其实是配置项） | 「（配置时区）」 |

用同一份真实配置跑 `--offline`，两边打印的请求路径与报文体是**逐字节一致**的。

另外，这次重写做了两轮**逐函数的行为对照审计**（拿原版代码当基准），
把"同一场景下会不会做出不同的事"逐条核了一遍；上面那张表里的每一条都是审计
实打实找出来的差异，改完之后每一条都补了对应的回归测试。
