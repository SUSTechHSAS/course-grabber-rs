# 教务系统抢课 · Rust 版

[course-grabber](https://github.com/SUSTechHSAS/course-grabber) 的 Rust 重写：
**放课瞬间精准首发 + 持续捡漏**，带自动登录、被踢重登录、写请求限流节拍器，
以及对服务器过载的容错。点选验证码的识别**直接编进可执行文件** ——
一个 **约 1.0 MB（1014 KiB）** 的文件就是全部，不需要 Python、不需要动态库、不需要模型文件。

> 这是一个**配置驱动**的工具：域名、接口路径、Cookie 名、密码加密密钥、候选教学班
> 全部写在本地 `config.json` 里（已被 `.gitignore` 忽略），仓库代码里没有任何具体学校的信息。
> 配置格式与原版**完全一致** —— 原来那份 `config.json` 可以原样拷过来
> （新增的多课程写法是向后兼容的扩展：只写单个 `course` 仍然照读，见「常驻与轮换」）。

```
                    ┌──────────────┐
   学号 + 密码 ───► │  自动登录     │ ──► 会话(token + cookie)
                    │  auth.rs     │        │
                    └──────────────┘        │ 被限流踢掉时自动重登
                            ▲               ▼
   启动 ──► 只读预检 ──► 对齐服务器时钟 ──► T0 错开首发 3 个班
                                                │
                              轮转调度（多课程；高频只读、读到空位才写）
                                                │
                                  已选课程列表出现目标教学班 = 抢到一门
                                                │
                                   抢齐所有课程 / Ctrl-C / 窗口到点才退出
```

## 1. 体积与速度

| | 原版（Python + PyInstaller） | 本仓库 |
| --- | ---: | ---: |
| 可执行文件 | 8,727,128 字节（8.3 MiB） | **约 1.0 MB（1014 KiB）** —— 8.4× |
| 下载的压缩包 | 8,623,811 字节（8.2 MiB） | **约 584 KiB** —— 14.4× |
| 运行时依赖 | 无（但打包时收了 CPython 解释器与标准库） | 无（一个静态链接好的二进制） |
| 验证码识别 | `libccm.so` + `python/solver.py`（约 250 KB，还要配对路径） | 编译进来的 Rust 依赖，模型 124 KB 编在二进制里 |
| 启动 | 解包 + 解释器启动约 0.3~1 s | 进程直接跑，毫秒级 |

识别本身用的就是 [click-captcha-matcher-rs](https://github.com/SUSTechHSAS/click-captcha-matcher-rs)
里的同一份代码与同一个模型（w16），所以**速度与准确率与那个库的实测数据一致**
（Ryzen 7 5700U 上 1.64 ms/张），没有为了压体积牺牲推理性能 ——
`opt-level` 全局用 `"s"`，那个 crate 单独抬回 `3`。

"无缝衔接"具体指：识别是一个**编译期依赖**，于是下面这些坑全都不存在了 ——
找不到 `libccm.so`、`python/` 目录指错、模型文件路径不对、`sys.path` 里同名模块串味、
打包时忘了带模型、换解释器重跑。一个文件拷过去就能跑。

## 2. 快速开始

### 下载预编译版

到 [Releases](https://github.com/SUSTechHSAS/course-grabber-rs/releases) 下载对应平台的一键包，
解压后直接跑：

```bash
./run.sh          # Linux / macOS
run.bat           # Windows（双击）
```

第一次运行会在可执行文件旁边生成 `config.json` 并告诉你该填什么。
想少填点就直接 `./course-grabber tui` —— 里面有个配置向导（四步），粘一条选课页网址就能把
"学校"那一节填好，见下面「配置界面」。
**不需要装任何东西** —— 不需要 Python，不需要 Rust，不需要动态库。

### 从源码构建

```bash
git clone https://github.com/SUSTechHSAS/click-captcha-matcher-rs ../click-captcha-matcher-rs
git clone https://github.com/SUSTechHSAS/course-grabber-rs
cd course-grabber-rs
cargo build --release          # 产物：target/release/course-grabber
```

识别库必须 clone 到**同级目录**（它是 path 依赖）。构建只需要 cargo，
`cargo build --release` 出来的那一个文件就是全部。

### 三步走

**用配置界面（推荐，一条网址起步）：**

```bash
# 1) 开界面，照「配置向导」一步一步走：
#    粘一条选课页网址 → 填学号密码 → 勾几个教学班，配置就齐了
./target/release/course-grabber tui

# 2) 演练（只读预检，绝不提交）→ 实战
./target/release/course-grabber
./target/release/course-grabber --live              # 等到 20:00 放课，打一个有限窗口
./target/release/course-grabber --live --forever    # 常驻：一直挂着轮转（见「常驻与轮换」）
```

**手写配置（不想用界面，或者老配置直接搬过来）：**

```bash
# 1) 配置（把原版的 config.json 拷过来也行）
cp config.example.json config.json
$EDITOR config.json          # 填域名、接口路径、Cookie 名、候选教学班……

# 2) 凭据（要用自动登录的话；也可以在上面那个界面的「凭据」一节里填）
mkdir -p ~/.config/course-grabber
cat > ~/.config/course-grabber/credentials.json <<'EOF'
{"student_id": "你的学号", "password": "你的密码"}
EOF
chmod 600 ~/.config/course-grabber/credentials.json

# 3) 演练（只读预检，绝不提交）→ 实战（19:50 启动，自己等到 20:00:00.000 首发）
./target/release/course-grabber
./target/release/course-grabber --live
```

见到「预检全部通过」再等放课。**不加 `--live` 永远不会提交任何东西。**

### 配置界面：`course-grabber tui`

```bash
course-grabber tui                       # 编辑程序自己找到的那份 config.json
course-grabber tui --config 别的文件      # 指定编辑哪一份（不存在就按模板新建）
course-grabber tui --credentials 凭据文件  # 单独指定凭据文件
```

#### 第一次用：配置向导（进去按 `w`，或第一次运行时自动开始）

**普通用户不需要知道任何一个接口路径。** 向导一步一步问，每问完一步就把结果显示出来：

```
第 1/4 步 · 学校地址
把浏览器地址栏里选课页的网址粘进来（Ctrl-L 全选、Ctrl-C，然后 Ctrl-V）。
只写域名也行 —— 我会去问服务器页面在哪。
网址 ▏ 127.0.0.1:38417
Enter 去问服务器（只读 GET）· Esc 退出向导 · Ctrl-C 放弃
```

**第 1 步：地址。下面四种粘法都认。**

| 你粘的 | 会发生什么 |
| --- | --- |
| `jw.example.edu.cn` | 只有域名也够。程序 `GET /`，服务器 302 到应用页 —— 路径就是从那一跳拿的 |
| `http://jw.example.edu.cn/` | 同上 |
| `http://…/xs/course/app/*default/index.do` | 直接从路径里认出上下文与页面路径 |
| `http://…/xs/course/app/*default/grablessons.do?token=…` | 浏览器地址栏里那条就是它；token 不会被保存 |

回车之后它会**去问服务器**（只发几个 GET，不登录、不提交），把每一步凭什么这么填都摊开：

```
✓ GET / → 302
✓ 服务器把 / 指到了 /xs/course/app/*default/index.do —— 页面路径就是从这儿来的
✓ 接口前缀验证过：GET /xs/course/app/student/vcode/image.do → 200 image/jpeg（验证码图片接口）
✓ / 没有 Date 头（跳过，不能拿它对时）
✓ 对时页取 /xs/course/ —— 实测只有它带 Date 头，对时要靠它
```

三件事值得说明，都是**实测出来**、不是猜的：

- **接口前缀 = 页面路径里 `*default` 前面那一整段上下文**（比如 `/xs/course/app`）。
  注意 `config.example.json` 里写的是 `/course-system/api` —— 那份是脱敏过的，
  照着它推会多出一段 `/api`，全 404。这里以真实系统为准。
- **接口前缀是验证过的**：拿登录前就会用到的验证码图片接口去试，返回 `200 image/jpeg` 才算数；
  试不通还会试 `前缀 + /api` 的写法。试不出来就**明说是猜的**，并告诉你怎么自己看一眼。
- **对时页必须先确认它带 `Date` 头**：有的学校根路径是另一台服务器接的（302 且没有 `Date`），
  拿它当对时页等于对时形同虚设。所以这里按「`/` → 上下文首段 → 上下文 → 页面」逐个试，选第一个真带 `Date` 的。

认不出的系统（路径里既没有 `*default` 也没有 `/api`）只填域名端口，并直说
"这套系统我认不出，剩下的照 config.example.json 手填" —— 猜错一个路径，用户看到的是一句
看不懂的 404，比一开始就说"我不认识"糟糕得多。

**第 2、3 步：学号、密码。** 只写进凭据文件（0600），界面不回显密码，也不会进 `config.json`。
覆盖已有凭据前会先留一份 `credentials.json.bak` —— 密码不像配置，写错了没法凭记忆恢复。

**第 4 步：把课程目录整个拉下来，自己挑。** 回车之后它会用你的凭据登录，
**把每一类课都拉一遍**（方案内 / 方案外 / 校公选 / 体育 / 慕课，按 `totalCount` 翻页拉全），
然后给你一张能滚、能筛、能按类型开关的列表：

```
拉到了 312 个教学班 · 空格勾选 · Enter 写入　批次 正选 · 校区 01 · 学生 测试同学　类型：1✓ 方案内课程 120  2✓ 方案外课程 40  3✗ 校公选课 100 …
筛选 ▏ 线性
[ ] 方案内课程      线性代数            01  张老师     星期三-3-5     星期三第3-5节 一教101     满=0 冲突=0 FANKC-0
[x] 方案内课程      线性代数            02  李老师     星期五-3-5     星期五第3-5节 二教202     满=0 冲突=0 FANKC-1
[ ] 方案外课程      线性代数            01  张老师     星期三-3-5     星期三第3-5节 一教101     满=0 冲突=0 FAWKC-0
[ ] 校公选课       线性代数            01  张老师     星期三-3-5     星期三第3-5节 一教101     满=0 冲突=0 XGXK-0
登录时服务器实际下发了这些会话 Cookie：JSESSIONID、_WEU —— 已把 cookies.session 补成这份名单
空格 勾选 · A 全选 · / 筛选 · 1-9 类型开关 · Enter 写入 · Esc 放弃
```

- **不用先想关键词**：整类课都在列表里。`/` 输入筛选词（课程名 / 教师 / 教学班号 /
  类型名都能搜），`1`-`9` 开关某一类，`空格` 勾、`A` 全选（只作用于看得见的那些）。
- **类型就写在每一行最前面**：同一门课在方案内 / 方案外 / 校公选下都可能开、名字一模一样 ——
  不标出类别，光靠名字根本分不清该勾哪个。
- **勾选跨类型也没问题**：写进配置时每个候选都带自己的 `type`，抢课提交时按各自的类别发
  （报文里的 `teachingClassType` 必须和那门课的类别一致，否则学校不认）。
- **冲突组是从上课地点里推出来的**（`星期三第3-5节 一教101` → `星期三-3-5`），
  这正是"同组互斥、跨组串行"那套策略的输入，手填最容易写错。推不出来（地点写成"待定"之类）
  就照实留空并提醒 —— 不会编一个看起来合理的值。
- **会话 Cookie 名单会自己补全**：登录时服务器实际下发的 Cookie 名如果比配置里列的多
  （脱敏后的示例配置就少了 `_WEU` 这种），程序会补上并**用新名单重新登录一次** ——
  少带一个 Cookie，后面每个接口都可能被判未登录，而这种错很难从报错看出来。

### 课程类型（`teachingClassType`）

目录查询和提交选课报文里都带着这个值，**它决定服务器回哪一类课**：

| 代码 | 是什么 |
| --- | --- |
| `FANKC` | 方案内课程（必修课基本都在这一类） |
| `FAWKC` | 方案外课程（示例配置里带的就是它） |
| `XGXK` | 校公选课 |
| `TYKC` | 体育课程 |
| `MOOC` | 慕课（还要在 `query_content` 里带 `MOOC:2,` 才查得到） |

以前"只能看到方案外课程"就是因为配置里写着 `FAWKC`，而查询只问这一类。
现在挑课屏**每一类都拉、每行都标类别**，勾了哪些类就把那门课的 `class_type` 定成第一类，
每个候选再各自带着自己的类别 —— 所以跨类型挑也不会发错、跨课程也不会发错。

（`TJKC` 本班推荐走的是另一个接口 `recommendedCourse.do`，本工具不带它；`FXKC` 辅修有些账号
会被学校直接拒。）

**收尾**：显示"将要写入哪两个文件"和候选数/冲突组，回车就保存。保存完回到编辑器，光标停在「目标课程」，
底部提示下一步：先跑 `course-grabber`（不加 `--live`）做只读预检。

> **两个联网动作都会先问**（"会用 2026****01 登录 xxx 查课程目录（只读），继续吗？"），
> 不按 `y` 一个包都不发。登录过程本身只读，全程不发任何写请求（自检里有断言钉住）。

#### 多门课：加课 / 删课 / 在几门之间切换

「目标课程」一节现在管的是**一整份课程清单**（`courses` 数组）。这一节最上面三行是：

| 行 | 按 Enter 干什么 |
| --- | --- |
| `⇄ 编辑下一门` | 在几门课之间轮换（当前编辑第几门显示在最上面的标题行里） |
| `＋ 再加一门目标课程` | 追加一门空课程，下面的字段立刻指向它 |
| `✕ 删掉当前这门课` | 删掉当前编辑的这一门（至少留一门） |

下面那组字段（名字 / 关键词 / 类别 / is_major / 查询模板）和候选列表**都只作用于
"当前这一门"**；「⇣ 拉课程目录」挑完也只写进当前这一门。老配置（只写单个 `course`）
进界面时会被自动搬进 `courses` 数组并在保存时写回新格式 —— 旧键不会留在文件里
（留在里面就会出现"界面改的那份程序不读"）。

#### 界面本身

```
 course-grabber 配置 · /home/you/course-grabber/config.json · ●未保存 · ✗2 处待修
 1 学校        │ ⤓ 粘贴选课网址（自动填这一节）
 2 凭据        │ ❓ 配置向导（从零到能跑，一步一步问）
 3 接口路径    │   域名 host                   jw.example.edu.cn
 4 Cookie 名   │   端口 port                   80
 5 密码加密    │   接口前缀 base_path          /course-system/api
 6 目标课程    │   业务页 page_path            /course-system/*default/index.do
 7 验证码      │   对时页 time_path            /
 8 节奏        │   referer_path                （未设置）
 9 网络        │   ⇅ 联网自检（只读探测这些路径是否真的存在）
 10 其它       │
域名 host = jw.example.edu.cn（s 保存）
↑↓ 移动 · ←→/Tab 换节 · Enter 编辑/执行 · a 加 d 删 · s 保存 · v 校验 · w 向导 · ? 帮助 · q 退出
```

它解决的问题很具体：config.json 有四十来个键，其中十个接口路径、三组加密密钥、
若干候选教学班 —— 手写很容易在逗号和引号上翻车，而**配置写错的代价是放课那一刻打不出去**。

- 左栏十节：学校、凭据、接口路径、Cookie 名、密码加密、目标课程、验证码、节奏、网络、其它
  （键位 `1`~`9`、`0` 直接跳）。光标停在哪一行，改的就是哪一行。
- 灰字显示的 `（默认 …）` 表示**文件里没写这个键**、程序现在用的是这个值；
  按 Enter 改成别的才会写进文件，清空则回到默认。所以"看到的"和"跑起来用的"不会对不上。
- 顶部一直显示校验状态（`✗2 处待修` / `⚠1 处提醒` / `✓ 完整`），按 `v` 看完整清单；
  校验过的项包括缺域名、接口路径没填齐、密钥不是 1~3 组、候选取不到、
  候选是不是还停在模板的示例值、凭据文件的权限。
- **原样保留**：只改你动过的键，`_comment` 说明、自定义键、老配置里的陌生字段
  全部按原顺序原样写回；保存是 2 空格缩进，和 `config.example.json` 一个风格。
- **不碰磁盘直到你按 `s`**，退出时有没保存的修改会先问你。
- 联网任务跑在后台线程里，进度（验证码识别、批次、目录条数）实时滚在界面上，界面不卡。
- 想跳过向导直接改也行：`Esc` 关掉，每一行按 Enter 就是编辑。
- Windows 上暂不提供（那边的控制台要走 Win32 API）；直接编辑 `config.json` 一样能跑。

## 3. 常用开关

`--help` 里有全部参数，这里只列最常用的：

| 参数 | 说明 |
| --- | --- |
| `--live` | 真正提交。不加就只做只读预检 |
| `--at 20:00:00` | 出手时刻（配置时区）。已过则立刻开打，`--tomorrow` 才等到明天 |
| `--now` | 不等了，立刻开打 |
| `--forever` | **常驻**：不设窗口上限，一直轮转下去（抢齐 / Ctrl-C 才停）。见下面「常驻与轮换」 |
| `--poll 3` | 每秒最多读几个候选的容量，默认 3。**读取总量是常数**，候选再多也是这个速率 |
| `--window 600` | 不用 `--forever` 时，出手后持续尝试多少秒（放课瞬间学校会重排数据，给短了等于放弃） |
| `--priority 001,002` | 覆盖配置里的候选顺序（可只写 ID 后缀） |
| `--single` | 首发只打第一优先级那一个班（默认打组内前 3 个） |
| `--stagger 0.10` | 多班首发之间错开多少秒 |
| `--write-timeout 4` | 单发写请求最长占用几秒（爆发期自动压到 2 秒） |
| `--no-relogin` | 关掉自动登录链路，只用 `--cookie` / `--url` 给的会话 |
| `--relogin-max 4` | 一次运行最多自动登录几次 |
| `--offline` | 不联网，只打印将要发送的报文 |

**随时可以停**：`Ctrl-C` 是优雅停止（不再发新请求 → 收尾 → 打印结果），再按一次立刻退出。

退出码：`0` 全部抢到 · `1` 一个都没抢到 · `3` 抢到一部分 · `4` 同一门课/同一时段中了多个
（需要你手动退掉多余的）· `2` 参数或配置有错。

### 常驻与轮换：`--forever` + 多课程

```bash
# 挂着一整晚：放课之外也常有人退课被放出来
./target/release/course-grabber --live --forever
```

放课只是"名额最集中的那一瞬间"，平时也一直有人退课。常驻模式就是在整个选课轮次里
一直轮转：

- **高频只读、低频写、读到就快写。** 每个时间片只读**一个**候选的容量
  （`--poll N` = 每秒读几个），读到有空位就**立刻**发这一发写请求；读到"已满"就
  什么都不做；读到"读不到"（学校在初始化、容量接口返回 0/0）就照打一发探针。
- **读取总量是常数**：一个时间片只问一个候选，所以候选再多也只是轮得慢一些，
  不会把请求量堆起来。`--poll 3` ≈ 3 请求/秒（约 26 万/天）；读接口实测 20 req/s
  都毫发无伤，想更保守就 `--poll 1`。
- **为什么写请求必须低频**：写接口实测滚动 1 秒最多 3 发，第 4 发会被限流**并当场
  作废整个会话**（前三晚 20:00 全是这么死的）。没有空位时写出去的每一发都只会被回
  「超过课程容量」，纯属烧额度。
- **所有目标课程一起轮换**：配置里的候选合并成一张总表，按时段轮转。
- **常驻不发"放课瞬间盲打"的那 3 发**：轮转循环已经在跑、读到空位就出手，而实测
  放课那一瞬间学校正好在重排数据、会话当场作废（连续三晚），那 3 发大概率是废的。
  想保留正点盲打就别用 `--forever`（`--window` 那条老路完全没变）。
- **不会空转**：连续 3 次收到「不在选课开放时间范围内」就认为这一轮选课结束了，
  打印一句说明后收工 —— 常驻是好几天的事，轮次一关再挂着没有意义。

多课程写在 `config.json` 的 `courses` 数组里（老配置只写单个 `course` 一样能用）：

```jsonc
"courses": [
  { "name": "线性代数", "keyword": "线性代数", "class_type": "FAWKC",
    "candidates": [ { "id": "…306", "label": "06班 周三3-5", "group": "星期三-3-5" } ] },
  { "name": "大学物理", "keyword": "大学物理", "class_type": "FANKC",
    "candidates": [ { "id": "…888", "label": "01班 周三3-5", "group": "星期三-3-5" } ] }
]
```

**两条不变量保证不会双选**（多课程之后它们成了唯一的依据，轮转调度本身不再负责这件事）：

| 不变量 | 为什么 |
| --- | --- |
| 每门课最多中一个 | 同一门课中两个教学班也算双选 |
| 每个冲突组（星期-节次）最多中一个 | 组名是时间键，所以**两门课的时间冲突天然落在同一组**，不会同时中 |

抢到一门课之后其余课程继续轮转，**全部抢齐才退出**（`Ctrl-C` 随时停）。
配置界面（`course-grabber tui`）的「目标课程」一节里可以加课 / 删课 / 在几门课之间
切换，每门课各自「⇣ 拉课程目录」挑候选。

## 4. 安全设计（写在代码里的硬约束）

1. **没有任何退选/删除志愿的代码路径**，全文不含 `operationType":"2"`。
   没有任何函数能移除你已选的课程。（CI 里有一条测试专门断言提交报文里的
   `operationType` 恒为 `"1"`。）
2. **默认不提交**，必须显式 `--live`。
3. **已在已选列表 → 直接退出**，不做任何提交。
4. **白名单**：只提交预检阶段解析出的候选教学班。
5. **只认已选列表**：提交接口说「成功」不算成功，必须已选课程里出现完整教学班 ID。
6. **密码错立刻熔断**：服务端回「登录名或密码不正确」就永久放弃自动登录，
   绝不用错误密码反复试探（避免账号被锁）。
7. **写请求绝不自动重放**：只读请求被判过期会自动重登并重放，写请求不会 ——
   避免重复提交。
8. **写请求节拍器**：所有写请求（首发 + 重试）共用同一份额度，任何路径都凑不出
   超出「每滚动窗口 N 发」的第 N+1 发。

## 5. 工程笔记（这些结论都是实测出来的，代码把它们固化成了硬约束）

### 写接口的限流模型

在一套实际系统上量到的（换成你自己的学校务必重测）：

- **滚动 1 秒内最多 3 发写请求**，第 4 发会返回「请求过快」并且**当场作废整个会话**。
- 1 发/秒、2 发/秒可以一直打，没有累计上限。
- **只读请求不占写额度**。
- **多发「同时」发 ≠ 多次机会**：同一瞬间打出去的 3 发里只有 1 发会被真正评估，
  另外 2 发拿到的是空 msg 的并发拒绝；**错开 0.06 秒以上**才是 3 次真机会。
- 被限流作废的会话不会自己恢复，但**重登录能立刻刷新额度**。

`pacer.rs` 就是把这些变成代码里的硬约束：窗口内最多 N 发、相邻两发至少错开
`min_gap`、并且「遗忘」一条记录要等满 `窗口 + 安全边界`（贴着边界发会踩线）。

顺带说明：原版 Python 里 `pacing.min_gap` / `http.write_timeout` 这两个配置键其实
**不生效**（代码写死了命令行默认值）。Rust 版让它们生效了，所以换学校时改配置就有用。

### 服务器过载时会发生什么

放课瞬间全校同时提交，服务端会过载：请求挂住不回、网关 5xx、返回 HTML 错误页。
原版在这里会「死等」（一次写请求 15 秒超时 × 内部重试 2 次 = 30 秒），
一个挂住的请求就能吃掉整个窗口。用「会按剧本过载的假学校」量过的对比：

| 过载剧本（20 秒窗口，前 3 秒过载） | 改之前 | 改之后 |
| --- | ---: | ---: |
| 连接挂住不回 | 2 发 / **16.1 秒** | 6 发 / **3.9 秒** |
| 响应慢 6 秒 | 2 发 / **16.1 秒** | 6 发 / **3.9 秒** |
| 网关 502 + HTML | 7 发 / 3.1 秒 | 9 发 / 3.6 秒 |

### 目标时刻已过就直接开打（预检按需裁剪）

`--at` 的时间已经过了（或 `--now`）时，脚本会自动跳过**只为"精确对点"服务的预检**：

| 步骤 | 对点时 | 已过点时 |
| --- | --- | --- |
| 校验会话 | 做 | **做**（必须） |
| 读已选课程（安全护栏） | 做 | **做**（40ms） |
| 从课程目录解析候选 | 做 | 跳过（候选直接用配置里的） |
| 容量快照 | 做 | 跳过 |
| 对齐服务器时钟（25 次采样） | 做 | **跳过（省约 2.5 秒）** |

实测：会话建立之后到写出第一发，**从 2.7 秒降到 39 毫秒**；整进程从启动到出手约 1.5~2 秒。

### 服务端「正在初始化」时**绝不能安静下来**（一次真实事故）

放课瞬间服务端会进入一段「系统正在初始化」的状态，实测持续了**约 3 分钟**。这段时间：

- 写请求全部被拒：「正在初始化，请稍候…」
- **容量接口返回 `0/0`** —— 那是"没有数据"，不是"没有空位"
- 已选课程列表返回空、课程目录返回空
- 会话可能被清掉，登录接口短暂返回 `认证失败`

**踩过的坑**：脚本里有个"先读容量、没空位就不发写请求"的优化。初始化期间容量返回
`0/0`，被算成"已满"，于是脚本在**整个放课窗口里安静地轮询了 56 秒**，一发写请求都没发出去。

两处修正：`has_slot()` 把 `total <= 0` 当成"查不到"（返回「照打」）；
初始化期间停机时间不计入"第一组多少秒没名额就换组"的倒计时，
并把试探节奏改成「每 0.6 秒 1 发」（多打无意义，但必须快速试探 ——
服务恢复的那一瞬间才是位子真正可抢的时刻）。

回归测试：`tests/offline.rs::init_outage_keeps_firing` 用一个"容量全返回 0/0 +
写请求全被拒"的假服务端驱动**真实的重试循环**，断言停机期间仍在发写请求。

> **放课当晚不要反复重启脚本。** 每次重启都要重新登录（同一账号单会话，还会顶掉
> 上一次的会话）+ 重新跑预检，首发那 3 发又会全部撞在"正在初始化"上。正确做法是
> 一个实例 + 足够长的 `--window`（比如 600 秒），它会自己等系统恢复。

### 放课瞬间「登不回来」绝不能收工（2026-09-26 事故）

放课那一瞬间学校会把整个选课子系统推倒重排，**会话当场作废**：写请求开始回
「请求数据与登录者身份不一致，非法请求。」，只读接口也报「登录过期」，
而认证接口同时返回 `#E2140600091 认证失败`。当天实际时间线：

| 时刻 | 事件 |
| ---: | --- |
| T+0.000 | 首发#0 → `FULL 该课程超过课容量` —— **会话还是好的** |
| T+0.156 | 首发#1 → `EXPIRED 请求数据与登录者身份不一致` |
| T+0.361 | 首发#2 → 同上 |
| T+0.589 | 只读 `courseResult.do` 也报过期 → 启动自动重登录 |
| T+1.077 | 登录被 `#E2140600091` 拒绝 |
| T+4.355 | 再登一次，又被拒绝 |
| **T+4.4** | **整个进程退出** |

窗口本来有 90 秒，脚本在第 4.4 秒就自己收工了。旧代码在 `Verdict::Expired` 里只调用
**一次** `recover()`，失败就 `return` —— 而学校大约二十秒后就能重新登录
（09-25 那晚 20:00:22 一个新起的进程登录成功了）。**连续两晚同一个死法。**

| 缺陷 | 修法 |
| --- | --- |
| 一次 `recover()` 失败 = 放弃整个窗口 | `Verdict::Expired` 改成**一直试到窗口结束**（退避 0.5 → 1 → 2 → 3 秒封顶）；期间不写（写出去也必被拒），登回来就立刻接着抢 |
| 窗口里被 `--relogin-max 4` 卡住 | 窗口内把上限放宽（`ReloginManager::relax_limit`）；只按墙钟收口。真·凭据错误仍走 `BadCredentials` 熔断，不受影响 |
| 默认 `--window 90` 根本等不到系统恢复 | 默认改成 **600 秒**（这是唯一一处故意偏离原版默认值的地方） |

回归测试：`tests/offline.rs::auth_outage_at_the_window_does_not_abandon_the_run`。
假服务端在前 4 秒把会话判死、登录一律回 `#E2140600091`，断言**停机结束后仍在下发
写请求**。把修正退回旧写法，它立刻变红 —— 整个任务 **2.4 秒**就退出了，
和当天 4.4 秒的死法是同一个。

> **窗口要给足。** 重排期间写请求会被连续拒绝二十秒起步，09-25 那晚到 20:00:23
> 容量接口还全是 `0/0`。抢到了会立刻收工，所以窗口长没有代价。

顺带修掉一个会误导复盘的日志：`首发#N 写出于 T+56.1ms` 里的 `T+` 是**相对这一发
自己的计划时刻**（放课时刻 + N×`--stagger`），不是相对放课时刻。当天那三发的真实
出手时刻是 T+0.000 / T+0.156 / T+0.361，只看旧日志很容易读成"错开 100ms 失效了"。
现在两个偏移都打出来。

### 「候选全满」的安静期，别把换组一起静掉（2026-09-27 事故）

上面那条修正生效了：放课瞬间会话被作废之后脚本自己登回来，一路跑到窗口结束
（10 分钟、94 发写请求、中途没再掉线）。但那晚**第二冲突组一发都没试**：

```
20:00:00.202  T+0.000  首发#0 → EXPIRED 请求数据与登录者身份不一致   ← 三发全废
20:00:15.971  ✓ 会话已登回来，立刻接着抢                             ← 修正生效
20:01:11.164  最后一条写请求（学校还在回「选课系统正在初始化」）
20:10:00.966  进入冲突组 星期五-3-5: ["318"]                        ← 正好是窗口截止那一刻
```

20:01:11 之后是**9 分钟的空白**。两件事叠在一起：

- 学校初始化结束、容量接口开始回真实数字，而四个候选全是 `非主选 2/2` ——
  `has_slot()` 返回"已满"，于是脚本**安静地只读轮询**。这是设计如此（不把账号打成
  风控），但它一行日志都不打，人盯着屏幕分不清是"在等"还是"已经死了"。
- 更糟的是「停机结束」这个状态**只认写请求的判决**（FULL / 正常回复）。没有写请求
  ⇒ 这个状态永远认不出来 ⇒ `outage_since` 一直挂着 ⇒ 换组条件里那句
  `outage_since <= 0` 把换组永久挡住。**318 组（4 个非主选名额，唯一名额多一倍的
  一组）从头到尾没被碰过。**

修法与回归测试：

| 缺陷 | 修法 |
| --- | --- |
| 没有写请求时「停机结束」永远认不出来 | 容量接口能读出真实数字（`Some(_)`，**不管有没有空位**）同样说明系统回来了：清 `outage_since`、把停机时长补回换组倒计时 |
| 安静期一行日志都没有 | 候选全满时每 30 秒打一行心跳（含已等多久） |

`tests/offline.rs::full_candidates_after_the_outage_still_roll_to_the_next_group`：
假服务端（新增 `Mode::OutageThenFull`）先初始化 2 秒，之后容量接口回真实数字但全部满员，
断言**第二个冲突组的教学班被问过容量**。退回旧逻辑它立刻变红 —— 问过的一直只有第一组。

### 同一账号只有一个会话

连续登录 A→B→C，每次都回头复查前面的会话：

```
登录 A 之后: A=活
登录 B 之后: A=死  B=活
登录 C 之后: A=死  B=死  C=活
```

推论：**跑脚本时别在浏览器里刷新同一套系统**，**只能跑一个实例**
（脚本用 PID 锁拦住了第二个），也**别指望多开会话把额度翻倍**。

## 7. 与原版（Python）的差异

**保留了**：配置格式、命令行参数的语义与默认值、全部安全约束、
上面那些实测出来的限流/对时/重试策略、退出码（0 抢到 / 1 没抢到 / 2 参数或配置问题 /
3 会话不可用 / 4 疑似双选需要人工处理）、日志的措辞与节奏。

**去掉了**：

- **读 Chrome Cookie 那条回退路径**。它的价值是"没有凭据文件时也能跑"，代价是
  要自己实现 SQLite 读取 + AES-128-CBC + PBKDF2 + Secret Service(D-Bus) ——
  而原版打包版里那条路其实也是**不通**的（`import dbus` 在打包环境里根本不存在，
  实际只会拿 "peanuts" 那把钥匙，桌面版 Chrome 早就不用它了）。
  现在会话来源是两个明确的东西：**凭据文件自动登录**，或者显式的 `--cookie` / `--url`。
  因此也去掉了 `--profile` / `--no-chrome`（保留为无操作参数，老命令不会报错）。
- **`tools/` 下那 7 个探针脚本**（rate-limit / burst-shape / concurrent /
  session-budget / sessions / overload / auth）。它们是"换学校时重新测限流参数"
  用的研究工具，依赖原版的 Python 模块；要重测请用原版仓库里那份，
  本仓库不再重复实现。
- `--captcha-model-dir`（识别库不再需要指向目录；`--captcha-model` 仍可用外部 `.ccm`）。
- Windows 上强制 UTF-8 输出的那段黑客代码（Rust 不会因为打印中文而崩）。
- Windows 上的"优雅停止"信号处理（CRT 的信号语义不同，见 `grab.rs` 的注释）。

**改掉的（都是原版里的坑）**：

| --- | --- | --- |
| `pacing.min_gap` / `http.write_timeout` 配置 | 写了但不生效 | **生效**（命令行优先） |

**新增的**：

- **配置界面 `course-grabber tui`**（原版没有）。手写那份四十来个键的 JSON 太容易出错，
  而配置写错的代价是放课那一刻打不出去。它只改你动过的键，其余原样写回；
  校验不合规的地方在标题栏上直接报数。见上面「配置界面」一节。
- **从零起步的配置向导**（也在 `tui` 里，`w` 或第一次运行自动开始）：粘一条网址（**只写域名也行**，
  服务器会把页面路径告诉我们）→ 域名/端口/接口前缀/页面路径/对时页全自动填好并**实测验证**，
  文件里缺的键照参考实现补齐；再填学号密码，然后让程序**登录把每一类课程目录都拉下来**，
  你在列表里按类型 / 名字筛着挑 —— 候选教学班 ID、冲突组（星期-节次）、每门课属于哪一类、
  缺的会话 Cookie，这几样最不可能手填对的东西从此不用手填。
  两个联网动作都会先弹确认，而且全程只读。
- **凭据文件也能在界面里填**，落盘就是 0600。

用同一份真实配置跑 `--offline`，两边打印的请求路径与报文体是**逐字节一致**的。

另外，这次重写做了两轮**逐函数的行为对照审计**（拿原版代码当基准），
把"同一场景下会不会做出不同的事"逐条核了一遍；上面那张表里的每一条都是审计
实打实找出来的差异，改完之后每一条都补了对应的回归测试。
